7. BUSINESS LOGIC
-------------------------

MONEY:
  Decimal(str(value)) everywhere, quantize to 2 DP, ROUND_HALF_UP
  Return as strings in JSON: "1200.00"

PER-LINE CALCULATIONS (server-side, never trust client):
  amount          = unit_price x qty
  discount_amount = amount x discount_percent / 100
  taxable         = amount - discount_amount
  vat_amount      = taxable x vat_percent / 100

INVOICE TOTALS (server-side):
  subtotal       = sum(amount)
  total_discount = sum(discount_amount)
  total_vat      = sum(vat_amount)
  total          = subtotal - total_discount + total_vat

FOC (Free Of Charge):
  foc_qty shown on print, does NOT affect amount/discount/VAT
  Does NOT decrement inventory

AUTO-NUMBERING (server-side, daily reset):
  Invoices:   INV-YYYY-MM-DD:NNNN
  Quotations: QTN-YYYY-MM-DD:NNNN

DOCUMENT TYPES:
  invoice   - has payments, decrements inventory, statuses:
              Draft/Sent/Paid/Overdue
  quotation - no payments, no inventory, statuses:
              Draft/Sent/Accepted/Rejected

MULTI-COMPANY:
  Each invoice has company_id (default 1 = Aspicom LLC)
  Company dropdown in the invoice form
  Dropdown is LOCKED after invoice is created
  Print uses the INVOICE'S company, not the currently-selected one
  Each company has its own logo + stamp uploaded via:
    POST /api/companies/<id>/logo
    POST /api/companies/<id>/stamp
  Files saved as: uploads/company-<id>-logo.<ext>
  Never delete companies (they have logo/stamp/history)

MULTI-CURRENCY:
  Each invoice has currency (USD or AED, default USD)
  Currency dropdown in the invoice form (NOT locked - editable)
  Print uses the invoice's currency symbol
  Statements/VAT Report keep their own logic (see below)

INVENTORY:
  Decremented on invoice creation only
  Case-insensitive product name matching
  Missing product = skip silently
  Balance clamped at 0 (never negative)

LOW-STOCK ALERT:
  Definition: inventory.balance < 20 (fixed threshold)
  Bell icon top-right of every page shows count
  Bell click -> dropdown lists low-stock products
  Dashboard shows a bar chart of low-stock items
  Bars scaled to max 20, rotating color per bar
  Par level shown as dashed line on each bar

AUDIT TRAIL (invoice_audit):
  One row per changed field on PUT
  action: create/update/delete/status_change
  old_value, new_value stored as strings

PAYMENTS:
  invoice.amount_paid is running total
  balance = total - amount_paid
  Auto-flips status to 'Paid' when balance hits 0
  Overpayment rejected with 409

CLIENT STATEMENTS (/api/clients/<id>/statement):
  Shows all invoices + payments for one client
  Opening balance = sum of transactions before `from` date
  Closing balance = opening + invoiced - paid (within range)
  Aging: 5 buckets (Current / 1-30 / 31-60 / 61-90 / 90+)
    based on `due` date (falls back to `issued`)
  VAT card shows total VAT for that client's invoices
  Transactions table has a VAT column
  Only Sent/Paid/Overdue invoices count (Drafts excluded)

VAT REPORT (/api/vat-report):
  Company-wide VAT summary across ALL invoices
  Filters: from/to, company_id, client_id, currency
  Only document_type='invoice' and status IN (Sent, Paid, Overdue)
  Returns totals, by_company, by_currency, invoices list
  Each invoice shows: subtotal, discount, taxable, vat, total
  Where:
    subtotal = invoices.subtotal (before discount)
    discount = subtotal + vat - total (derived)
    taxable  = total - vat (VAT base)
    vat      = invoices.vat
    total    = invoices.total
  Currencies NOT converted - by_currency splits totals

AUTHENTICATION:
  Currently AUTH_ENABLED=false (dev mode - no login required)
  See AUTHENTICATION STATUS section at the bottom for details

8. DATABASE SCHEMA
-------------------------

TABLE: clients
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY
  name VARCHAR(255) NOT NULL
  address TEXT
  po_box VARCHAR(50)
  trn VARCHAR(50)
  email VARCHAR(255)
  created_at TIMESTAMP

TABLE: invoices  (holds invoices + quotations)
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY
  company_id INT UNSIGNED NOT NULL DEFAULT 1 (FK -> company.id)
  currency VARCHAR(3) NOT NULL DEFAULT 'USD'
  document_type ENUM('invoice','quotation') NOT NULL DEFAULT 'invoice'
  client_id INT UNSIGNED NOT NULL (FK -> clients.id, RESTRICT)
  lpo_number VARCHAR(100)
  invoice_number VARCHAR(100) NOT NULL UNIQUE
  issued DATE
  due DATE
  valid_until DATE
  status ENUM('Draft','Sent','Paid','Overdue','Accepted','Rejected')
  vat_percent DECIMAL(5,2) DEFAULT 0
  notes TEXT
  subtotal DECIMAL(12,2) DEFAULT 0
  vat DECIMAL(12,2) DEFAULT 0
  total DECIMAL(12,2) DEFAULT 0
  amount_paid DECIMAL(12,2) DEFAULT 0
  created_at TIMESTAMP
  INDEX idx_document_type, idx_invoices_company

TABLE: invoice_items
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY
  invoice_id INT UNSIGNED NOT NULL (FK -> invoices.id, CASCADE)
  product_name VARCHAR(255) NOT NULL
  brand VARCHAR(255)
  unit_price DECIMAL(12,2) NOT NULL
  qty DECIMAL(10,2) NOT NULL
  foc_qty DECIMAL(10,2) DEFAULT 0
  discount_percent DECIMAL(5,2) DEFAULT 0
  discount_amount DECIMAL(12,2) DEFAULT 0
  amount DECIMAL(12,2) DEFAULT 0
  vat_percent DECIMAL(5,2) DEFAULT 0
  vat_amount DECIMAL(12,2) DEFAULT 0

TABLE: invoice_payments
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY
  invoice_id INT UNSIGNED NOT NULL (FK -> invoices.id, CASCADE)
  amount DECIMAL(12,2) NOT NULL
  paid_date DATE NOT NULL
  payment_method ENUM('cash','bank_transfer','card','cheque','other')
  reference VARCHAR(255)
  notes TEXT
  created_at TIMESTAMP

TABLE: inventory
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY
  product VARCHAR(255) NOT NULL UNIQUE
  brand VARCHAR(255)
  price DECIMAL(12,2) DEFAULT 0
  vat_percent DECIMAL(5,2) DEFAULT 5
  par_level DECIMAL(10,2) DEFAULT 0
  balance DECIMAL(10,2) DEFAULT 0
  updated_at TIMESTAMP

TABLE: company  (multi-row now)
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY
  name VARCHAR(255)
  address TEXT
  po_box VARCHAR(50)
  trn VARCHAR(50)
  phone VARCHAR(50)
  email VARCHAR(255)
  website VARCHAR(255)
  signee VARCHAR(255)
  logo_path VARCHAR(500)
  stamp_path VARCHAR(500)
  (Existing row: id=1, name='Aspicom LLC', po_box='515000',
   trn='100441082300003')

TABLE: parsed_invoices  (supplier PDFs)
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY
  source_pdf VARCHAR(500)
  supplier_name VARCHAR(255)
  header_trn VARCHAR(50)
  lpo_number VARCHAR(100)
  invoice_number VARCHAR(100)
  date DATE
  subtotal, vat, grand_total DECIMAL(12,2)
  raw_json JSON
  imported_at TIMESTAMP
  UNIQUE (supplier_name, invoice_number)

TABLE: import_log
  id, source_pdf, status ENUM('success','failed','duplicate',
  'ocr_fallback'), message, imported_at

TABLE: invoice_audit
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY
  invoice_id INT UNSIGNED (no FK - survives deletes)
  action ENUM('create','update','delete','status_change')
  field_name VARCHAR(100)
  old_value TEXT
  new_value TEXT
  changed_at TIMESTAMP

TABLE: users  (Phase 1 - LOCAL ONLY)
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY
  username VARCHAR(50) NOT NULL UNIQUE
  password_hash VARCHAR(255) NOT NULL
  full_name VARCHAR(100)
  email VARCHAR(255)
  role ENUM('admin','user') NOT NULL DEFAULT 'user'
  is_active TINYINT(1) NOT NULL DEFAULT 1
  last_login TIMESTAMP NULL

10. CRITICAL PATTERNS
-------------------------

1. IDs from HTML are STRINGS -> parseInt(id, 10) before use.

2. Data-id attribute vs actual id:
   HTML sets `data-id="${x.id}"` (string)
   Always parse before comparing to numeric IDs.

3. Money in JS:
   Backend returns strings ("1200.00")
   fmt() accepts both strings and numbers
   fmt(n, currency) - pass currency for correct symbol

4. Line endings:
   Files use LF (\n), NOT CRLF
   PowerShell find/replace patches must match LF
   Multi-line heredoc patches are unreliable - use SINGLE-LINE
   or TWO-LINE anchors

5. After HTML/JS changes:
   Hard refresh (Ctrl+Shift+R) in browser
   Check DevTools Console for red errors

6. After .py changes:
   Flask debug mode auto-reloads
   But safest to Ctrl+C and re-run Flask

7. Browser extensions (Copilot, ChatGPT):
   Inject HTML into localhost pages -> steal click events
   Use Incognito when debugging odd behavior

8. ALWAYS start Flask with venv Python (see section 16)

PHASE 1 — DETAILED SPEC (Stock Movement Foundation)
=========================================================

DELIVERABLE
  Every stock change is logged with full context.

MOVEMENT TABLE: stock_movements
  id              INT UNSIGNED AUTO_INCREMENT PRIMARY KEY
  inventory_id    INT UNSIGNED NOT NULL (FK -> inventory.id, RESTRICT)
  product_name    VARCHAR(255) NOT NULL (snapshot)
  change_qty      DECIMAL(10,2) NOT NULL (positive = in, negative = out)
  balance_after   DECIMAL(10,2) NOT NULL (snapshot)
  reason          ENUM('initial','invoice_created','invoice_deleted',
                       'invoice_edited','quotation_converted',
                       'stock_in','stock_out','damage','expiry',
                       'return','rtv','correction') NOT NULL
  reference_id    INT UNSIGNED NULL (invoice_id if applicable)
  reference_label VARCHAR(255) NULL (invoice number)
  notes           TEXT NULL
  created_by      INT UNSIGNED NULL (users.id)
  created_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP

  INDEX on inventory_id, reason, created_at, reference_id

GRANULARITY
  Per line item. Invoice with 5 products = 5 movement rows.

LOGGING TRIGGERS
  1. Invoice created (invoice only, not quotation)
       ? for each line: create movement (reason=invoice_created, qty=-qty)
  2. Invoice deleted (invoice only)
       ? for each line: create movement (reason=invoice_deleted, qty=+qty)
       ? also: restore inventory.balance
  3. Invoice edited (qty change on line items)
       ? for each changed line: create movement (reason=invoice_edited)
       ? also: adjust inventory.balance by the delta
  4. Quotation converted to invoice
       ? for each line: create movement (reason=quotation_converted, qty=-qty)
  5. Manual adjustments (Phase 2, but endpoint stubbed here)

BACKFILL (one-time)
  For every existing inventory row:
    INSERT movement (reason='initial', change_qty=balance, balance_after=balance)

ENDPOINTS
  GET  /api/inventory/<id>/movements
       Returns all movements for one product.
       Query: from, to (date), reason (filter), limit (default 100)

  GET  /api/stock-movements
       Global feed. Filters: from, to, reason, inventory_id, search (product name)
       Pagination: limit + offset. Default limit 100.

  POST /api/inventory/<id>/adjust   (Phase 2, but stub now)
       Body: { change_qty, reason, notes }
       Admin only. Creates movement + adjusts balance.

PERMISSIONS
  - View movements: any authenticated user
  - Adjust stock: admin only (Phase 2)

FRONTEND
  1. Inventory row ? "Movements" button (opens modal showing that product's history)
  2. New sidebar item "Movements" between Inventory and Supplier Bills
     - Global table: Date | Product | Change | Balance After | Reason | Reference | By
     - Filters: date range, reason, product search
  3. Colored reason pills (e.g. green for stock_in, red for stock_out)
